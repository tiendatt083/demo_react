Bản Chất Forms Trong React & Form State

Chuyển từ HTML DOM thuần sang mô hình Two-Way & Nguyên tắc Single Source of Truth

Nguyên Lý Nền Tảng

Single Source of Truth

  • HTML DOM thuần: Thẻ <input> tự lưu trữ value ngầm trong DOM.
  • React Two-Way Pattern: React State là nguồn chân lý duy nhất điều khiển giao diện.
  • Thách thức lớn: Cập nhật state không đúng cách sẽ gây re-render thừa toàn bộ form.
⚠️ Bài toán UX:

Không được báo lỗi đỏ ngay khi user vừa mở trang chưa kịp nhập gì!

Cấu Trúc Dữ Liệu

Bóc Tách 6 Thành Phần Của Form State

values: Đối tượng chứa dữ liệu hiện tại của các trường.
errors: Danh sách vi phạm validation gắn liền với từng ô input.
touched: Cờ xác định user đã focus rồi blur (chặn báo lỗi sớm).
dirty / pristine: Xác định dữ liệu đã bị sửa đổi so với mặc định ban đầu.
isSubmitting: Đánh dấu request đang gửi để khóa nút bấm.
isValid: Cờ tổng thể xác định form hợp lệ 100% để submit.

Controlled vs. Uncontrolled Components

So sánh hai trường phái thiết kế biểu mẫu & Bẫy cảnh báo kinh điển

Tiêu chí so sánh Controlled Components Uncontrolled Components
Nơi lưu state React State (useState / useReducer) DOM Tree tự nhiên (HTMLInputElement)
Cách truy xuất value={state} & onChange={...} useRef() hoặc new FormData()
Re-render Impact Re-render trên MỌI phím gõ (10 phím = 10 lần render) ZERO Re-render khi gõ phím (Đọc ref khi cần)
Mục đích tối ưu Form nhỏ 1-3 ô, format tức thời (số thẻ) Form vừa & lớn, Form nghiệp vụ phức tạp
🚨 Bẫy Cảnh Báo: "Changing an uncontrolled input to be controlled"

Nguyên nhân: Khởi tạo useState() trống (nhận undefined). Frame 1 React coi là Uncontrolled. Khi gõ phím, state thành string, ép input biến thành Controlled ➔ Gây bất đồng bộ kiến trúc!

// ❌ SAI: const [name, setName] = useState(); // undefined! <input value={name} onChange={...} /> // ✅ ĐÚNG: Luôn khởi tạo chuỗi rỗng const [name, setName] = useState('');

Form Validation, A11y & Submit Handling

Chiến lược kích hoạt validation, chuẩn Screen Reader & Chống Double Submit

Chiến Lược Bắt Lỗi
  • Instant (onChange): Validate trên từng phím gõ (Kiểm tra độ mạnh Password).
  • Afterward (onBlur) - Chuẩn Vàng UX: Báo lỗi khi rời ô nhập. Không làm gián đoạn lúc đang gõ.
  • On Submit: Kiểm tra tổng thể trước khi gửi dữ liệu.

Gọi e.preventDefault() chặn reload trang. Bắt buộc khóa nút bấm với disabled={isSubmitting} để ngăn người dùng bấm nhiều lần khi mạng lag làm trừ tiền thẻ lặp lại!

Xử Lý Tải File & Quản Lý Bộ Nhớ (RAM)

Validation kích thước/MIME, tạo Blob Preview & Nguy cơ rò rỉ bộ nhớ (Memory Leak)

Quy Trình Kiểm Tra File
  • Truy xuất File: Đọc đối tượng từ e.target.files[0] (FileList).
  • Client Validation: Chặn ngay nếu file.size > 2MB hoặc MIME không phải JPG/PNG.
  • Xem trước tức thì: URL.createObjectURL(file) tạo URL tạm trỏ vào RAM.
🧠 Cơ Chế Gây Rò Rỉ Bộ Nhớ (Memory Leak):

Blob URL neo trực tiếp vào RAM trình duyệt. Garbage Collector KHÔNG THỂ tự thu hồi nếu lập trình viên không chủ động gọi lệnh hủy!

Giải Pháp Dọn Dẹp Bắt Buộc
AvatarUpload.tsx
const [previewUrl, setPreviewUrl] = useState<string | null>(null); const handleFileChange = (e) => { const file = e.target.files?.[0]; if (file) { // 1. Thu hồi URL cũ trước khi tạo URL mới if (previewUrl) URL.revokeObjectURL(previewUrl); setPreviewUrl(URL.createObjectURL(file)); } }; // 2. Cleanup function khi unmount component useEffect(() => { return () => { if (previewUrl) URL.revokeObjectURL(previewUrl); }; }, [previewUrl]);

Error Boundary & Lá Chắn Chống Sập

Ngăn chặn White Screen of Death & Phân tích 4 trường hợp Error Boundary bất lực

Cấu Trúc Bắt Buộc (Class Component)

React chưa có Hook tương đương cho 2 phương thức vòng đời này:

export class ErrorBoundary extends React.Component { state = { hasError: false, error: null }; // 1. Cập nhật state để render Fallback UI static getDerivedStateFromError(error) { return { hasError: true, error }; } // 2. Gửi log lỗi lên hệ thống Sentry/LogRocket componentDidCatch(error, info) { logToMonitoring(error, info.componentStack); } render() { if (this.state.hasError) { return <ErrorFallbackUI />; } return this.props.children; } }
Bẫy Tử Huyệt Kỹ Thuật
🛑 4 Lỗi Error Boundary KHÔNG THỂ Bắt Được
  • 1. Event Handlers (onClick, onSubmit): Chạy ngoài render phase. ➔ Bắt buộc dùng try...catch.
  • 2. Asynchronous Code: Các lệnh trong setTimeout, fetch().then(), promises.
  • 3. Server-Side Rendering (SSR): Lỗi phát sinh trong tiến trình server Node.js.
  • 4. Lỗi ngay trong Error Boundary: Component bảo vệ bị văng lỗi thì không thể tự che chở cho chính nó.

CSS Physical vs. CSS Logical Properties
CSS Cũ (Physical ❌) CSS Mới (Logical ✅) Hành vi khi sang RTL

padding-right: 12px; padding-inline-end: 12px; Tự đảo thành padding-left
left: 0; inset-inline-start: 0; Tự neo vào mép phải
border-left: 4px; border-inline-start: 4px; Viền tự nhảy sang bên phải
